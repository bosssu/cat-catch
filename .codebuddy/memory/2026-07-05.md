## 侧边栏根本原因修复 - chrome.tabs.getCurrent 在侧边栏返回 undefined (17:16)
### 根因
- m3u8.js 初始化链: `setRequestHeaders(cb) → cb → chrome.tabs.getCurrent(tab) → tab.index`
- **侧边栏不是 tab**，`chrome.tabs.getCurrent` 在侧边栏返回 `undefined`
- 访问 `tab.index` 抛出 TypeError，`init()` 永远不执行，`#loading` 始终显示，CSS 不注入

### 修复
- **`js/m3u8.js`**: `chrome.tabs.getCurrent(tab)` 中加入 `if (!tab)` 保护，`currentIndex=0, currentTabId=0`，直接 `awaitG(init)`
- **`js/mpd.js`**: `chrome.tabs.getCurrent(tabs)` 中 `tabs.id` → `tabs ? tabs.id : 0` 防止 TypeError
- **`js/function.js` openParser()**: 新增检测 `location.href.includes('sidepanel=1')` → 侧边栏内走 `window.location.href` 而非 sendMessage
- **`js/popup.js` [go]**: 路径加 `/` 前缀
- **`js/background.js` openSidePanel**: 改用 `async/await` 确保 `setOptions` 完成后才 `open`

## 解析按钮无反应修复 (17:22)
### 根因
- 上一轮 `background.js` 的 `openSidePanel` handler 用了 `async/await` + `chrome.sidePanel.setOptions({...})` 的 Promise 形式
- 在 Service Worker 中，`chrome.sidePanel.setOptions` 的 Promise 版本可能在某些 Chrome 版本不可靠（返回的 Promise 不等同于 callback）
- 导致 `await` 后 `open()` 未正确执行，侧边栏不出现

### 修复
- `background.js` openSidePanel handler 回退为 callback 形式：
  - `chrome.sidePanel.setOptions({tabId, path, enabled}, callback)` → 回调中检查 `lastError` → `chrome.sidePanel.open({tabId})`
  - 错误均通过 `console.error` 输出，方便调试
